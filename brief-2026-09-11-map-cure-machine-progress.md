## What ChatGPT answered — digest

### [3] "Where we are" (answer to [0])

Formalised the machine as a loop: READ → MODEL → TARGET (identity-preserving
youthful state) → PLAN → ACT (drugs · gene edit · epigenetic edit · immune ·
cells · regeneration · organs · neural repair) → VERIFY → repeat.

A September-2026 frontier table, scored 0 (conceptual) to 5 (general-purpose
mature), as *best narrow demonstration / universal-machine readiness*:

| Required capability | narrow | universal | note |
|---|---|---|---|
| Read molecular/cellular state | 4 | 2 | rich omics/imaging; cannot inspect every cell in a living person; HCA still assembling |
| Know what "healthy" looks like | 3 | 1 | no counterfactual model of *you, optimally healthy and young* |
| Diagnose causal defects | 4 | 2 | strong for infections/mutations/cancers; weak for interacting aging/immune/neural failure |
| Precisely edit DNA | 4 | 2 | CRISPR therapy approved for blood disorders; in-vivo base editing durable in humans |
| Deliver edits to arbitrary cells | 3 | 1 | **giant bottleneck**: liver/blood/local tissues tractable; arbitrary cell-type-specific delivery is not |
| Replace broken cell populations | 3 | 2 | stem-cell islets restored insulin production (10/12 full-dose insulin-independent at 1 yr, one early trial); Parkinson's neuron replacement in humans |
| Regenerate complex tissue | 3 | 1 | organoids/engineered tissue advancing; mature vascularised innervated anatomy *inside the patient* far away |
| Replace whole organs | 4 | 2 | transplantation works; gene-edited pig kidneys supported human physiology; rejection unsolved |
| Reverse cellular aging | 2 | 1 | claimed: first human received partial epigenetic reprogramming June 2026 (eye) — **unverified here; recorded as a question, not a claim** |
| Repair CNS circuitry | 2 | 1 | Parkinson's / spinal-cord cell replacement in humans; circuit reconstruction unresolved |
| Restore lost identity-bearing brain information | 1 | ~0 | information-theoretic boundary; mm³ human cortex reconstructed post-mortem ≈ 150M synapses |
| Closed-loop verify and correct | 4 | 2 | narrow closed loops exist; no whole-body state feedback |
| Integrate into one autonomous repair system | 1 | 0 | nobody has anything approaching it |

Key framing: progress is *not* "unknown science → magic → cure" but the
independent acquisition of primitive operations (atlases, causal models, gene
and epigenetic editing, delivery, immune engineering, cell replacement, tissue
engineering, organ replacement, rejuvenation, neural interfaces, biosensors,
closed-loop control). Percent-complete is meaningless because dependencies are
not additive. Four blockers to watch: **universal biological addressability**
(deliver(payload, organ, cell_type, state, location) — nowhere near), **a causal
human state model**, **safe multiplex control**, **information-preserving neural
repair**. The target is not "youngest possible state" but a constrained
optimisation: maximise health/function/resilience/youthful physiology subject to
preserving identity, memories, learned abilities, anatomy, agency; avoiding
malignancy, immune pathology, unacceptable risk. A 20-year-old molecular state
with your current memories is a counterfactual organism that never existed.
Proposed making humanrepairmap.com a technological dependency graph (100–300
capability nodes: current frontier → human evidence → bottleneck → required
breakthrough → groups → trials → dependencies → progress over time).

### [6] Useful for researchers / accelerate by decades (answer to [4])

Only if it is built as *infrastructure for deciding what research should
happen next* — a Human Repair Research Operating System: goal → what prevents
this (dependency/blocker graph: knowledge gaps, capability gaps, translation
gaps) → what should we do next (highest-value experiment) → new evidence →
update the graph → repeat. **"Accelerate by decades" is an objective, not
something we can responsibly promise**; the credible mechanism is removing
years of wasted serial research. Existing pieces: Human Cell Atlas, Open
Targets (June 2026 release with cell-type-level evidence), NIH Bridge2AI,
ARPA-H IGoR (launched May 2026), DeepEvidence (Nature Machine Intelligence,
July 2026). Missing: goal-directed integration — *given the end goal of
comprehensive human repair, what are the critical unresolved capabilities,
what evidence supports each, and which experiment reduces the most important
uncertainty next?*

Mechanisms: recursive decomposition of every capability until an
experimentally actionable question is reached; **every `?` becomes an object**
(why it matters / evidence by rung / contradictions / replication / known
unknowns / next discriminating experiment / downstream capabilities / groups /
datasets / protocols / funding / collaborators needed); **critical path** —
"experiment Q is unexpectedly upstream of 63 capabilities"; a first-pass
priority heuristic *P(resolvable) × InformationGain × CriticalPathImpact ×
CrossDomainSpillover / (Cost × Time)*, later proper Bayesian decision analysis;
**map failures** (null results first-class; "STOP: 17 similar experiments exist,
6 succeeded, 11 failed; strongest predictor of failure was …"); the unit is a
**causal claim + context + evidence + replication + contradiction + provenance**,
not a paper; human-genetic support raises clinical success ~2.6× (Nature 2024)
so better upstream evidence selection materially changes downstream success.
Mission wording: internal north star stays "anyone → black box → healthiest
attainable, youthful, identity-preserving state"; externally "an open,
machine-readable map of the scientific capabilities, evidence, dependencies and
unresolved questions required for comprehensive human repair", then "we help
researchers identify which unanswered questions are blocking the greatest
amount of downstream progress". Four stages: MAP → GRAPH → PLANNER → NETWORK →
LOOP. First target: ONE domain (suggested partial reprogramming/rejuvenation),
100–300 claims, 20–50 questions, 5–10 blockers, then hand it to researchers:
*"does this graph tell you something useful that would otherwise have taken
hours/days — or change what experiment you would run?"*

### [9] All injuries and diseases, instantly (answer to [7])

Yes, that is the stronger north star: restore arbitrary biological damage. The
word to change is "instantly": SECONDS–MINUTES prevent irreversible damage →
MINUTES–HOURS restore critical function → HOURS–DAYS reconstruct biology →
eventually near-complete restoration. **Do not organise by disease** (that
inherits medicine's silos); organise all pathology as failures of biological
state — STRUCTURAL damage (tears, fractures, bleeding, burns, organ loss) ·
BIOLOGICAL state error (infection, malignancy, inflammation, autoimmunity,
senescence, mutations, toxins) · INFORMATIONAL damage (neural circuitry,
memory, sensory maps) — and identify a finite library of **repair primitives**:
(1) stop catastrophic processes, (2) remove foreign/pathological agents, (3)
repair plumbing (vascularisation is a central unsolved problem), (4) repair
structure (a fracture or a knife wound is a *composition* of primitives:
haemostasis + decontamination + vascular repair + nerve repair + muscle
regeneration + ECM reconstruction + skin regeneration), (5) reconstruct tissue
rather than wait for healing (leap from damage to original architecture without
the inflammation → provisional matrix → scar → remodelling pathway; in-situ
biomanufacturing is a research direction; fibrosis is rarely reversible today).
Diseases become repair programs (cancer, autoimmunity, genetic disease, heart
attack, stroke as ordered primitive sequences). **The one profound exception:
information that has ceased to exist** — the boundary is *repair anything
whose correct state can still be inferred or reconstructed from surviving
information*. Top of the graph: SURVIVAL · REPAIR · RESTORATION, all under
PRESERVE SELF; beneath: SENSE / UNDERSTAND / MANIPULATE / CONTROL / VERIFY.
Fractures, sepsis, cancer, wounds and aging are not separate projects — they
are **test suites**; a capability is universal only when it generalises across
them. Long-term objective: *reduce medicine to the smallest set of
general-purpose operations capable of diagnosing and reversing arbitrary damage
to a human being.*

vascular-regeneration node is one node, reached from either map). IA: Universal

failure, neurological damage, …) and Rejuvenation (cellular aging, epigenetic
restoration, senescence, stem-cell exhaustion, fibrosis, immune aging, organ
rejuvenation, systemic rejuvenation) over a SHARED CAPABILITY GRAPH (delivery,
vascularisation, immune engineering, cell replacement, genome editing,
epigenetic editing, tissue morphogenesis, neural reconstruction, biosensing,
causal modelling, …). Don't force the choice every visit; add "Explore full
capability graph". Label the first map "Universal Repair", not "Disease &
Injury". First screen: *What would it take to repair the human body?* —
**Universal Repair** (from trauma and infection to cancer and organ failure) ·
**Rejuvenation** (from biological aging to restored youthful function) · **Full
Research Graph** (capabilities, dependencies, evidence, blockers, next
experiments).

### [15] The most capable version (answer to [12])

Not "a website with two maps": the website is the interface to a continuously
updating research system. Lock in **one canonical Human Repair Graph, many
projections**. Four graph layers: (1) EVIDENCE — paper → claim → experiment →
result → replication; (2) CAUSAL BIOLOGY — molecular → cellular → tissue →
organ → organism; (3) CAPABILITY/DEPENDENCY — what must humanity become capable
of; (4) RESEARCH-ACTION — question → experiment → protocol → lab → funding →
result. Do not rebuild layers 1–2 (OpenAlex ~320M works; Monarch; Open Targets;
Every Cure MATRIX ~60M drug–disease pairs). **HRM's unique contribution is
layers 3–4.** The killer feature is research prioritisation, not search
(example blocker page: downstream capabilities affected, known approaches,
failed approaches, unresolved discriminating questions, best current question,
proposed discriminating experiment with expected information gain, cost,
duration, available labs, protocols). ARPA-H IGoR (mechanistic models → AI
finds gaps → optimal experiment design → standard protocols → lab marketplace,
≥10× faster validation) is **complementary**: HRM tells an IGoR-like engine
*which* questions dominate expected time-to-general-human-repair. Make the
dependency model a **probabilistic AND/OR graph** (systemic rejuvenation = safe
mechanism AND multi-tissue delivery AND cancer control; delivery = AAV OR LNP OR
cells); objective *maximise expected reduction in time-to-capability per
research-dollar and researcher-hour*. **Every assertion inspectable**: CLAIM /
CONTEXT (species, strain, sex, age, model, cell type, tissue, intervention,
dose, route, timing) / MEASUREMENT (assay, endpoint, baseline, effect,
uncertainty) / EVIDENCE (n, controls, blinding, randomisation) / STATUS
(preprint, peer-reviewed, replicated, contradicted, retracted) / PROVENANCE
(paper, figure, table, dataset, exact passage); states machine-extracted →
machine-cross-checked → community-reviewed → domain-expert-validated →
independently-replicated. **Negative results first-class** (structured "we
tried … result: none", raw data, protocol; enables cross-experiment pattern
detection, e.g. "difference correlated with delivery route STRONG, promoter
STRONG; untested: vector B + promoter C"). **Do not invent another biomedical
ontology**: inherit Biolink/OBO for gene, protein, disease, phenotype, cell,
anatomy, chemical, organism; add only RepairCapability, RepairPrimitive,
TargetState, FailureState, CapabilityRequirement, AlternativeCapability,
ResearchBlocker, KnowledgeGap, DiscriminatingExperiment and the relations
Enables/Blocks/EvidenceFor/EvidenceAgainst/Replicates/Contradicts/Resolves.
Public site simple (two entrances → graph); researchers get a workstation (MAP
| QUESTIONS | EVIDENCE | EXPERIMENTS | LABS | DATA); protocols interoperate with
protocols.io / ClinicalTrials.gov FHIR. Make the research network part of the
graph (who knows / who can run / who can fund / what exists; OpenAlex as
substrate). **Build in six stages**: 1 define the Capability Schema (spend
disproportionate effort) · 2 one proving ground (a regeneration problem touching
both maps: ~100 capabilities, 500–2,000 claims, 30–100 questions) · 3 Evidence
Engine (ingest OpenAlex/PubMed/Europe PMC/ClinicalTrials; extract; normalise;
detect support/contradiction/replication) · 4 Gap/Experiment Engine · 5 close
the loop with real researchers (benchmark: surfaced a missed paper? exposed an
unsupported assumption? prevented a redundant experiment? changed a design?
created a collaboration? shortened time-to-decision?) · 6 only then the research
marketplace. Publish a ruthless impact dashboard. Eventually a **Repair
Compiler** (goal → decomposition → dependencies → evidence → hypotheses →
discriminating measurements → experiment candidates → feasibility → labs →
information gain → research plan; funder portfolio allocation). The moat is the
capability graph + expert-curated evidence + dependency model + experimental
history + real-world outcomes of predictions, kept open (FAIR/Bridge2AI). First
thing to build is not the homepage: **Human Repair Capability Model v0.1**.

### [18] Inviting future models and institutions (answer to [16])

**API-first scientific substrate for intelligence; the website is one client.**
Principle: *anything a human can discover or do through the UI must be
discoverable and operable by a machine through a stable, documented interface.*
Radically machine-readable claims (JSON with ids, context in NCBITaxon etc.,
evidence and contradiction ids, confidence with its method, provenance with
review status). **Observation, interpretation and prediction are separate
objects; never overwrite history.** Interoperate with W3C PROV and RO-Crate.
Expose **research operations**, not just retrieval: search_entities, get_claim,
get_primary_evidence, get_subgraph · trace_dependency, find_blockers,
find_contradictions, find_replications · compare_hypotheses,
compute_critical_path, rank_research_questions · get_protocol, find_dataset,
find_lab_capability · propose_claim, challenge_claim, propose_dependency,
propose_experiment · submit_result, submit_negative_result, submit_replication ·
forecast_outcome, register_prediction, evaluate_prediction. MCP is an adapter,
not the architecture. **Prospective prediction registry** as a
contamination-free benchmark: models and expert panels lock predictions on
G(t), reality resolves them, calibration accumulates ("can your model move the
Human Repair frontier?"). A machine-consumable corpus (correctly licensed
sources + structured claims + outcomes + dependencies + contradictions +
negative results + protocols + predictions + adjudications) as API, JSON-LD,
RDF, Parquet, JSONL, immutable versioned snapshots ("HRM Graph 2027.03"),
change feed, RO-Crates. Executable computational science (CWL). Federation:
institutions run their own node beside their private data (hospital, biobank,
pharma); compute goes to the data; FHIR and GA4GH for clinical/genomic interop.
Pay institutions back in utility (living evidence pages, replication tracking,
negative-result preservation, collaborator matching, credit for confirmed
claims / contradictions found / failed paths documented / replications);
ORCID and ROR identifiers. **AI as collaborator, never epistemic authority**:
proposals carry proposed_by (type, model, version, timestamp, evidence
accessed, method) and validated_by; epistemic weight comes from prediction →
experiment → reality, symmetrically for models and laureates. Multiple models
compete and critique; preserve every independent forecast before consensus.
Eventually the graph dispatches work (with legal/ethical/biosafety gates for
wet-lab; an enormous safe region of synthesis, reanalysis, prioritisation,
replication identification). **Governing test for every engineering decision:
"Could an intelligence we haven't invented yet use this dataset and system
substantially better than we can?"**

### [21] How to begin (answer to [19])

Prove that one real biomedical frontier can be represented better than a
researcher's literature workflow. Not scraping millions of papers, not a fancy
graph UI, not training a model. **P0 proving ground: scarless functional tissue
repair after injury** — it sits across both maps (wounds/trauma/burns/surgery
above; fibrosis/ECM aging/immune aging/stem-cell function/vascular regeneration
below) and decomposes into generalisable capabilities: stop bleeding → control
inflammation → prevent infection → restore vasculature → restore ECM →
regenerate correct cell populations → restore innervation → restore tissue
geometry → avoid fibrosis → verify normal function. Repository: `schema/`
(capability, claim, evidence, experiment, source), `ontology/` (repair
primitives, relationships, mappings), `graph/` (the proving-ground graph),
`evidence/`, `api/`, `web/` — **the graph files are the product**; the site
renders them, the AI proposes against them, the API exposes them; no scientific
meaning lives only in components or prose. Steps: 1 formally define six object
types (Goal, Capability, Question, Claim, Experiment, Evidence) and a small
relation vocabulary (REQUIRES, ENABLES, ALTERNATIVE_TO, BLOCKED_BY, SUPPORTS,
CONTRADICTS, REPLICATES, TESTS, RESOLVES, MEASURES); 2 **manually** build the
first 30–50 capabilities (do not let an LLM invent the ontology; the
COMPLETE SKIN REPAIR decomposition: immediate stabilisation, contamination
control, structural reconstruction incl. appendages and innervation,
biological control, functional restoration) asking of each "is this genuinely
a capability, can it fail independently, would solving it unlock others?";
3 attach real evidence to ~10 nodes (what do we believe, why, in what
organism, under what conditions, how strong, replicated, contradicted,
unknown); 4 provenance non-negotiable from day one (paper/DOI/PMID, figure,
extraction model + schema version + timestamp, reviewer + status); 5 AI
generates proposals, never silent truth (raw source → AI extraction →
candidate → cross-source verification → review → canonical graph); 6 one
genuinely useful researcher query — *"What currently prevents scarless, fully
functional regeneration of adult human skin?"* returning critical unsolved
capabilities (appendage architecture, organised microvasculature, peripheral
innervation, fibroblast state without impairing closure, native ECM
organisation, spatial morphogenesis), each with evidence, uncertainty,
contradictions, dependencies, open questions, candidate experiments; 7 only
then the website (restrained: two entrances → scarless tissue repair →
capability frontier → node panel: capability, evidence, questions,
dependencies, experiments, contradictions, people/labs, datasets); 8 expose
the machine interface immediately (GET /capabilities/:id, /dependencies,
/questions/:id, /claims/:id/evidence, /graph?root=; later POST proposals and
predictions; bulk graph.jsonl/parquet/jsonld). **First milestone: one repair
dependency graph a domain researcher judges more useful than their normal
literature search.** A strong v0.1: 1 repair challenge, 30–50 capabilities,
100–200 edges, 100–300 claims, 50–100 primary sources, 20 unresolved
questions, 5–10 contradictions, 5 candidate experiments, 100% provenance, 1
researcher-facing graph, 1 machine API. Then test it brutally with a researcher
(what dependencies are wrong, what is missing, what is overstated, where is
correlation mistaken for causality, what null results are absent; *would this
change what you read next / experiment on next?*). Then expand: severe wounds,
burns, surgical recovery, fibrosis, muscle, cardiac, organ repair; peripheral
nerve; fracture; myocardium; infection/sepsis; cancer; systemic rejuvenation —
and watch common primitives converge. If the core representation is wrong,
scaling it gives a much larger wrong system.

## What this session took from it (decisions applied in v0.3)

- The graph files are the product; one graph, two projections (`universal-repair`, `rejuvenation`) plus the full graph.
- Object types: goal, capability, question, claim, experiment, source (+ prediction; + the existing cell and route records, projected in rather than discarded).
- Relations stored once, inverses derived; AND/OR requirement groups.
- Machine interface first: JSON API, structured MCP results, JSON Schemas served, bulk export, versioned manifest, prediction registry.
- P0 proving ground = scarless functional skin repair, seeded with manually reasoned capabilities, questions, claims and sources — every one `ai-proposed`, every source carrying a machine `resolution` record separate from human reading.
- Nothing in this file or the graph is clinical advice, and no date is forecast.
